# Frontend (Smart Doctor SPA)

React + TypeScript SPA: библиотека клинреков, просмотр оригинала PDF и форма протокола.
См. корневой [README](../README.md), [AGENTS.md](../AGENTS.md) и контракт API в [backend/API.md](../backend/API.md).

## Быстрый старт

Бэкенд должен быть запущен на `127.0.0.1:8000` (см. [backend/README.md](../backend/README.md)).

```bash
cd frontend
npm install
npm run dev          # http://localhost:5173
```

Vite слушает `localhost` (на Windows это IPv6), поэтому адрес `127.0.0.1:5173` не отвечает —
открывайте `http://localhost:5173`.

В PowerShell с политикой `AllSigned` файл `npm.ps1` не запускается — используйте `npm.cmd run dev`.

Vite проксирует `/api` на `127.0.0.1:8000` (см. `vite.config.ts`), поэтому приложение всегда
обращается к относительному `/api` и CORS не нужен. При смене `BACKEND_PORT`/`PORT` поправьте
`BACKEND_ORIGIN` в `vite.config.ts`.

## Статусы индексации и подсветка цитаты

После загрузки PDF бэкенд сам запускает индексацию, поэтому строка библиотеки меняется без
перезагрузки страницы:

- `uploaded` — «Загружен»: файл принят, индексация ещё не началась;
- `processing` — «Обрабатывается» и ход обработки: сколько фрагментов записано из общего числа;
- `ready` — «Готов к проверке» и признак векторизации: число фрагментов и модель эмбеддингов;
- `failed` — причина отказа и кнопка «Повторить» (повтор ставит клинрек в обработку заново).

Опрашиваются только строки с незавершённым статусом (`src/store/indexingStatus.ts`), опрос
прекращается на `ready`/`failed`. Признак векторизации показывается исключительно для `ready`:
обещать готовность раньше сервера нельзя.

Цитату можно открыть по адресу: `/library/<guideline_id>/view?chunk=<chunk_id>`. Просмотрщик
загружает фрагмент через `GET /api/chunks/{chunk_id}`, открывает страницу первого прямоугольника
и подсвечивает все прямоугольники фрагмента на текущей странице — фрагмент режется по смыслу и
может занимать две страницы и больше. Текст цитаты и её раздел показываются в шапке экрана.

Проверить вручную:

```bash
curl "http://127.0.0.1:8000/api/guidelines/<guideline_id>"          # статус и chunks_total
curl "http://127.0.0.1:8000/api/chunks/<chunk_id>"                  # текст и rects
curl -X POST "http://127.0.0.1:8000/api/guidelines/<guideline_id>/index"   # повтор индексации
```

## Слой API

```
src/api/
  schema.d.ts     типы, сгенерированные из ../openapi.json — руками не правятся
  client.ts       транспорт: getJson, postJson, sendNoContent, ApiError, разбор {"detail": ...}
  guidelines.ts   обёртки эндпоинтов клинреков и типы Guideline / GuidelineStatus

```

## Коды МКБ и удаление клинрека

Коды МКБ-10 задаются при загрузке PDF (поле «Коды МКБ-10», несколько — через запятую) и
показываются в строке библиотеки бейджами. Фильтр по коду живёт в адресе (`?icd=I10`) и
комбинируется с фильтром по статусу; сопоставление учитывает уточнение кода, поэтому `I10`
находит клинрек с кодом `I10.1`. Правила кода продублированы на клиенте
(`src/lib/icd.ts`) и на сервере — опечатка отклоняется до отправки.

Удаление двухшаговое: кнопка в строке спрашивает подтверждение, и только потом уходит
`DELETE /api/guidelines/{id}`. Отказ `409` означает идущую индексацию, `503` — недоступное
векторное хранилище; причина показывается в самой строке, а клинрек остаётся в списке.

## Экран протокола

`/protocol/new` — форма протокола: жалобы, код МКБ с названием диагноза, описание диагноза и
назначения (препараты и процедуры отдельными пунктами). Клинрек выбирается только из готовых к
проверке; при заполненном коде МКБ совпадающие клинреки идут первыми.

По кнопке «Проверить форму» уходит `POST /api/protocols/validate`: сервер проверяет форму,
подтверждает клинрек и возвращает атомарные пункты, которые пойдут в проверку. **Черновик не
сохраняется** — после перезагрузки страницы форма пуста, а соответствие клинреку пока не
считается: проверка появится следующим изменением. Логика формы и сборка запроса живут в
`src/store/protocolForm.ts` и покрыты тестами без DOM.

- **`ApiError`** всегда несёт HTTP-статус и читаемое сообщение. Бэкенд отдаёт `detail` строкой
  (400/404/413), объектом `{message, guideline_id}` (409) и массивом (422) — `parseErrorDetail`
  понимает все три вида, поэтому в интерфейс не попадает `[object Object]`, а идентификатор
  дубликата не теряется.
- **Статус недоступного сервера** — `ApiError` со статусом `0`.
- **Загрузка файла** идёт через `XMLHttpRequest` (`uploadGuideline`): только он сообщает о ходе
  отправки, а PDF бывает до 50 МБ.

### Обновление типов

`openapi.json` лежит в корне репозитория и обновляется вместе с бэкендом. После изменения контракта:

```bash
npm run gen:api      # ../openapi.json → src/api/schema.d.ts
```

Сгенерированный файл коммитится: сборка не должна зависеть от запущенного бэкенда.

## Просмотрщик PDF

Экран `/library/<guideline_id>/view?page=N` показывает оригинал клинрека через `pdfjs-dist`.

- **Worker.** `pdfjs-dist/build/pdf.worker.min.mjs` импортируется через `?url`, поэтому Vite
  складывает его в `assets/` собранного бандла. Путь настраивается один раз в
  `src/hooks/usePdfDocument.ts` (`GlobalWorkerOptions.workerSrc`); копировать worker в `public/`
  не нужно. Если после сборки вместо страниц пустой экран — проверьте, что файл worker'а попал в
  `dist/assets/`.
- **Range.** Документ открывается по адресу `/api/guidelines/{id}/file`, и PDF.js запрашивает
  файл частями (`Range: bytes=...`). Сервер отвечает `206 Partial Content`; проверка одной
  командой:

  ```bash
  curl -s -o /dev/null -D - -H "Range: bytes=0-7" \
    http://127.0.0.1:8000/api/guidelines/<guideline_id>/file
  ```

  Ожидается `206` и заголовок `Content-Range`. Проксирование через nginx в compose не покрыто
  автотестами: при `proxy_buffering` диапазоны могут превратиться в `200`, и тогда PDF.js
  скачает файл целиком.
- **Подсветка.** Вердикты пока не приходят, поэтому подсветку никто не запрашивает. Точка входа
  уже есть: `PdfViewer` отдаёт наружу `PdfViewerHandle.goTo({ page, bbox })` — прямое продолжение
  инварианта «клик по источнику → оригинальный PDF на нужной странице». Когда появится
  `GET /api/chunks/{chunk_id}`, координаты `bbox` из ответа нужно передать в `goTo`.

## Структура

```
src/
  api/          клиент к backend и сгенерированные типы
  components/   презентационные компоненты (без запросов)
  hooks/        загрузка данных и побочные эффекты
  lib/          форматирование значений и правила кода МКБ
  pages/        экраны: Library, Viewer, Protocol, 404
  store/        чистая логика состояния: список, удаление, форма протокола, параметры адреса
  styles/       токены и базовые стили
```

Правило проекта: компоненты презентационные, запросы и логика — в `api/`, `hooks/`, `store/`.

## Тесты

`npm run test` (Vitest, окружение `node`) покрывает то, что не требует браузера:

- `src/api` — разбор ошибок, query-параметры списка, адрес файла, тело загрузки, подписи статусов;
- `src/store` — слияние страниц без дублей, порядок и параметры запросов, параметры адреса,
  фазы удаления, правила формы протокола и сборка запроса на валидацию;
- `src/lib` — форматирование размера, даты и прогресса, правила и сопоставление кодов МКБ;
- дымовые рендеры (`react-dom/server`) — маршруты, строка списка и форма загрузки.

Что проверяется вручную в браузере: реальная отрисовка PDF, drag&drop, прогресс загрузки и
поведение при недоступном бэкенде.
