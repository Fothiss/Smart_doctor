# Smart_doctor# Smart Doctor

AI-ассистент для врача: проверка врачебного протокола на соответствие клиническим рекомендациям.

## Суть

Врач загружает PDF клинических рекомендаций, заполняет структурированную форму протокола — и получает отчёт: по каждому пункту вердикт (соответствует / предупреждение / не соответствует / не покрыто) с обязательной ссылкой на конкретный фрагмент клинрека.

**Ключевой принцип:** каждое утверждение системы подкреплено цитатой из источника. Без цитаты вердикт не выдаётся.

## Целевой пользователь

Один врач-пользователь (single-user MVP). Многопользовательский режим, роли и интеграции с МИС — вне рамок первой версии.

## Основной сценарий

1. **Библиотека клинреков** — загрузка PDF, парсинг, валидация, индексация
2. **Ввод протокола** — структурированная форма (МКБ, жалобы, анамнез, диагноз, обследования, лечение и т.д.) + выбор клинрека
3. **Отчёт** — таблица по пунктам: вердикт, комментарий, ссылка на чанк клинрека с подсветкой в оригинальном PDF
4. **Чат** (вторично) — уточняющие вопросы по текущему протоколу с цитатами
5. **История** — прошлые проверки, экспорт в PDF

## Функциональные блоки

- Ingestion: парсинг PDF → иерархический чанкинг → embeddings → векторная БД
- Protocol parser: разбиение формы на атомарные утверждения
- RAG: hybrid retrieval (BM25 + vector) + reranker
- Comparator: LLM со structured output, обязательный `chunk_id` для каждого вердикта
- Report generator: сводка + детальная таблица + блок «Требует внимания»
- Feedback loop: 👍/👎 на каждый вердикт

## Техническая архитектура (высокоуровнево)

- **Frontend:** SPA + PDF viewer (React/Vue + PDF.js)
- **Backend:** FastAPI
- **Очередь:** Redis
- **БД:** PostgreSQL (метаданные, история, feedback)
- **Векторная БД:** Qdrant
- **Хранилище PDF:** MinIO / локальная ФС
- **LLM:** через прокси (Claude / GPT-4 / GigaChat) — единая точка переключения
- **Embeddings:** локально или через API
- **Деплой:** Docker Compose (~8 контейнеров)

## Ключевые правила

- Каждый вердикт обязан ссылаться на существующий чанк клинрека
- `confidence < 0.6` → пункт уходит в «Требует внимания»
- Клик по источнику → оригинальный PDF на нужной странице с подсветкой
- Версионирование клинреков: старые отчёты привязаны к своей версии документа

## Метрики успеха MVP

| Метрика | Цель |
|---|---|
| Точность парсинга PDF | ≥ 95% текста, ≥ 90% таблиц |
| Retrieval recall@5 | ≥ 85% |
| Согласие врача с вердиктами | ≥ 80% |
| Вердиктов с валидной цитатой | 100% |
| Время обработки протокола | ≤ 30 сек |

## Вне рамок MVP

- Многопользовательский режим и роли
- Интеграция с МИС / ЕГИСЗ
- Локальные LLM
- Автообновление клинреков
- Мобильное приложение
- Fine-tuning на feedback

## Риски

- **Галлюцинации LLM** → structured output + обязательный chunk_id + порог confidence
- **Плохой парсинг PDF** → экран валидации + LLM-fallback для таблиц
- **Неточный retrieval** → hybrid search + reranker
- **Недоверие врача** → каждый вердикт кликабелен до оригинала
