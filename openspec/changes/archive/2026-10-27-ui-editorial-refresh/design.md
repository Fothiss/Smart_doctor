# Design

## Context

См. `proposal.md` — Why. Технические обстоятельства, которые определяют подход:

- Стилизация — 21 CSS-модуль рядом с `styles/tokens.css`; токены есть, но типо-шкалы, фокус-кольца,
  переходов и медиазапросов нет. Стили полей и подсказок продублированы в трёх-четырёх модулях.
- Архитектура фронтенда делит слой на презентационные компоненты, `hooks/`, `store/`, `lib/` и `api/`.
  Логика покрыта тестами в `node`-окружении через серверный рендер; DOM-тестов и `jsdom` нет.
- Действие подтверждения удаления — фазы в `store/deleteGuideline.ts` (`idle | confirming | deleting |
  error`), проверенные тестами. Экран библиотеки уже разводит состояния через `store/listView.ts`.
- PDF-просмотр построен на `PdfViewer` с переданными снаружи страницей и масштабом; масштаб считается
  в `lib/zoom.ts`, координаты подсветки — в `lib/bbox.ts`.
- `vite.config.ts` не содержит CSS-плагинов; nginx отдаёт статику из `dist` и не требует правок ради
  шрифтов.

## Goals / Non-Goals

**Goals:**

- Один источник оформления: токены в CSS, Tailwind-утилиты читают их, компоненты не вводят своих цветов.
- Закрыть реальные пробелы примитивами из UI-kit: диалог, комбобокс, тост, тултип, skeleton.
- Перевести экраны на новый стек по одному, не оставляя приложение в нерабочем состоянии между шагами.
- Сохранить текущее разделение «компонент презентационный — логика в хуках/сторе/lib».

**Non-Goals:**

- Экран вердикта и его компоненты (`SourceRef`, `ConfidenceMeter`) — бэкенд не отдаёт вердикт.
- Тёмная тема: `color-scheme` и структура токенов оставляют возможность, но второй палитры не делаем.
- Адаптация под мобильные экраны уже 1024px.
- Серверные счётчики статусов и поиск по названию в библиотеке — требуют нового API.
- Замена `pdfjs-dist`, изменение `PdfViewer` API и формата координат подсветки.

## Decisions

### D1. Tailwind CSS v4 + shadcn/ui поверх Radix

Основной стек: `tailwindcss` + `@tailwindcss/vite` для утилит, `shadcn/ui` как набор копируемых в
репозиторий компонентов на примитивах Radix, `lucide-react` для иконок, `class-variance-authority` +
`tailwind-merge` + `clsx` для вариантов и склейки классов.

Почему: недостающие элементы интерфейса — это ровно те примитивы, которые в Radix решены с
доступностью (фокус-трап, `aria-*`, клавиатура). Tailwind v4 конфигурируется в CSS, поэтому цвета можно
держать в одном `tokens.css` без второго источника истины в JS. shadcn не приносит своего рантайма:
код компонентов лежит в проекте и правится как обычные файлы, в бандл попадает только использованное.

Альтернативы и почему отклонены:

| Вариант | Причина отказа |
|---|---|
| MUI | Material-эстетика конфликтует с редакторским направлением; темизация под медицинский инструмент — борьба с дефолтами; крупный рантайм |
| Mantine | Узнаваемый «админский» вид из коробки, выход за него требует тех же усилий, что и своя библиотека |
| Radix Themes | Меньше контроля над деталями, нужные состояния всё равно приходится дорисовывать |
| Остаться на CSS-модулях | Диалог, комбобокс и тост пришлось бы писать и покрывать тестами вручную — 2+ дня только на примитивы |

### D2. Токены остаются в CSS, Tailwind читает их через `@theme inline`

`styles/tokens.css` объявляет переменные как раньше и служит единственным источником. Дополнительно
появляется блок `@theme inline`, который отображает те же переменные в утилиты Tailwind
(`bg-surface`, `text-muted`, `border-subtle`, `font-mono` и т.п.). Никаких значений цветов в разметке.

Почему не переносить палитру в `tailwind.config`: это создаёт второй список цветов и ровно ту
расходимость, от которой страдает текущий CSS. Прямые произвольные значения (`bg-[#fff]`) запрещены
правилом в `AGENTS.md`.

### D3. Типографика: Inter + JetBrains Mono, self-host

Inter (400/500/600) — интерфейс и заголовки; JetBrains Mono (400, `tnum`) — коды МКБ, номера
страниц, счётчики. Файлы woff2 в `frontend/public/fonts`, подключение через `@font-face` с
`font-display: swap`; preload только для Inter 400 (первый экран).

Засечки отброшены после ревью: для медицинского приложения Literata читается как «печатная книга» и
визуально старит интерфейс. Заголовки — Inter 600 со сжатым трекингом, иерархию даёт вес и размер, а
не другой шрифт. Цитата выделяется левой линейкой маркера, а не курсивом.

Mono остаётся: коды МКБ и страницы в таблице должны выравниваться по разрядам, пропорциональным
шрифтом этого не добиться без хрупких хаков.

Бюджет: ~300 КБ на 12 файлов (Inter 3 начертания × 3 подмножества + Mono). PDF.js всё равно занимает
основной вес бандла.

### D4. Палитра: холодная клиника, тил, маркер

Ключевое решение — холодные нейтральные поверхности и один клинический акцент, без тёплой «бумаги»:

| Роль | Токен | Значение |
|---|---|---|
| Фон приложения | `--color-bg` | `#f8fafc` |
| Поверхность | `--color-surface` | `#ffffff` |
| Приглушённый фон | `--color-surface-sunken` | `#f1f5f9` |
| Линии | `--color-border` / `--color-border-strong` | `#e2e8f0` / `#cbd5e1` |
| Текст / второстепенный | `--color-text` / `--color-text-muted` | `#1e293b` / `#475569` |
| Заголовки | `--color-ink` | `#0f172a` |
| Акцент и фокус | `--color-accent` | `#0f766e` (≈5.6:1 на белом) |
| Подсветка фрагмента | `--color-mark` | `#fcd34d` 45% + граница `#f59e0b` |

Почему тил, а не синий: `#2563eb` — цвет «всех» SaaS, а тил читается как клинический и не спорит с
жёлтым маркером. Подсветка цитаты остаётся самым ярким пятном: это смысл продукта, а не декор.
Второстепенный текст `#475569` на `#f8fafc` — ≈7:1, выше порога AA из спеки.

Статусы — приглушённые пары «фон + текст» на холодных оттенках (emerald/amber/red/slate); цвет всегда
идёт вместе с текстом и смысл статуса не меняет.

### D5. Поэтапная миграция вместо переписывания

Tailwind устанавливается и настраивается один раз; дальше экраны переводятся по одному, начиная с
пилота `GuidelineRow`. CSS-модули остаются на месте до соответствующего шага и удаляются вместе с
последним использующим их компонентом. Правило: **в одном компоненте либо Tailwind, либо CSS-модуль**,
новые CSS-модули не создаются.

Почему не переписать всё сразу: 21 модуль и работающее поведение, покрытое лишь частично, при
большом переписывании дадут длинный отрезок, где ничего нельзя проверить глазами. Поэтапный путь
позволяет после каждого шага видеть результат в браузере и откатывать один экран, а не весь рефактор.

### D6. Логика остаётся на месте, меняется только рендер

- `store/deleteGuideline.ts` не переписывается: `confirming` становится состоянием «диалог открыт».
  Диалог монтируется по `phase === 'confirming'`, `onConfirmDelete`/`onCancelDelete` остаются прежними
  колбэками. Это сохраняет тесты стора и спека-поведение.
- `store/listView.ts` продолжает выбирать состояние экрана; меняется только отрисовка `loading` —
  вместо `StateBox` рендерятся skeleton-строки.
- Фильтрация для комбобокса выносится в чистую функцию `lib/guidelineSearch.ts`
  (`filterGuidelines(items, query)`), сортировка по МКБ остаётся в `lib/icd.ts`. Компонент получает
  уже отфильтрованный список — по правилу «компоненты презентационные».
- Клавиатура просмотрщика: сопоставление «клавиша → действие» — чистая функция `lib/viewerKeys.ts`
  (принимает `KeyboardEvent`-подобный объект и контекст «фокус в поле/нет»), а сама подписка на
  `keydown` живёт в `ViewerPage`. Так основное поведение тестируется в `node`-окружении без DOM.
- Подгонка по ширине: чистая функция `fitScale(containerWidth, pageWidth)` в `lib/zoom.ts` рядом с
  существующими `zoomIn`/`zoomOut`.

### D7. Тестовая стратегия: `node`-тесты для логики, `jsdom` только для оверлеев

Существующие тесты остаются серверными и проверяют текст и адреса — это переживает смену разметки.
`jsdom` + `@testing-library/react` добавляются только для того, что без DOM не проверить: закрытие
диалога по Esc, возврат фокуса, поиск в комбобоксе, скрытие ошибки поля. Остальные проверки остаются
чистыми функциями.

### D8. Правка `AGENTS.md` — часть изменения

Правило «Минимальный UI-kit, без тяжёлых библиотек» заменяется описанием стека и правилом миграции
(см. `tasks.md`). Это документ процесса, а не артефакт OpenSpec, поэтому он меняется тем же изменением,
чтобы правило и код не расходились.

### D9. Уведомления только там, где результат не виден иначе

Успешная загрузка PDF подтверждается появлением строки в списке и исчезновением прогресса — отдельного
тоста не будет, чтобы не дублировать уже видимое. Тост показывается для исхода удаления (успех и отказ)
и для отказа загрузки, если причина не помещается в форму.

## Risks / Trade-offs

- **Два подхода к стилям сосуществуют, пока миграция не закончена** → список переведённых экранов
  фиксируется в `tasks.md`, новые CSS-модули запрещены правилом, каждый шаг удаляет модули экрана.
- **Шрифты добавляют вес и задержку первого рендера** → шесть файлов, `swap`, preload только Inter 400,
  системный fallback-стек сохраняется; при необходимости subset с `unicode-range` для кириллицы.
- **Radix-компоненты в серверном рендере могут давать предупреждения порталов** → дымовые тесты
  маршрутов не открывают оверлеи; тесты диалога/комбобокса идут в `jsdom`.
- **Визуальные регрессии не ловятся юнит-тестами** → в задачах каждой фазы есть ручной чек-лист
  (1024/1280/1440, Tab-обход, `prefers-reduced-motion`, контраст).
- **`GUIDELINE_STATUS_LABELS` и тексты ошибок легко «улучшить» при редизайне** → спека `design-system`
  прямо запрещает менять смысл; тесты на подписи статусов остаются.
- **Смена подписей в разметке ломает существующие тесты** → тесты обновляются в той же задаче, где
  меняется компонент, а не отдельным долгом.
- **Установка новых зависимостей в песочнице требует полного доступа** (`vite`/`vitest` вызывают
  `net use`) → шаг установки выполняется с полным доступом, npm-кэш локальный.
- **`shadcn` тянет свои дефолтные стили, которые могут победить токены** → компоненты правятся на
  месте: классы вариантов ссылаются на токены, дефолтные палитры удаляются сразу при добавлении.

## Migration Plan

1. Установить зависимости, включить `@tailwindcss/vite` в `vite.config.ts`, добавить `@import`
   Tailwind в `styles/app.css` (порядок: токены → `@theme inline` → базовый слой).
2. Ввести токены v2 и шрифты; убедиться, что старые CSS-модули продолжают работать на новых токенах.
3. Пилот: `GuidelineRow` на Tailwind + новые примитивы; проверить тесты и вид; шаг считается
   приёмкой перед остальными экранами.
4. Библиотека, затем просмотрщик, затем форма протокола — по задачам; каждый экран удаляет свои
   CSS-модули.
5. Удалить ставший ненужным `StateBox` (или оставить только как обёртку для пустых состояний), обновить
   `AGENTS.md` и `frontend/README.md`.

Откат: пока CSS-модули живы, любой экран откатывается возвратом его файлов; после шага 5 откат —
`git revert` изменения целиком. Бэкенд и контракты API не затрагиваются, поэтому данные и ссылки
остаются валидными на любом шаге.
