# Proposal

## Why

Интерфейс работает, но выглядит как внутренняя админка: один вес у всего, дефолтные браузерные кнопки
рядом с синей primary, нет типо-шкалы и единой палитры, ни одного `:focus-visible`, ни одного `@media`,
ни одного перехода. Врач читает PDF клинрека в инструменте, где итог — доверие к цитате, а цитата
сейчас оформлена как второстепенная подпись.

Правило «минимальный UI-kit, без тяжёлых библиотек» мешало закрыть реальные пробелы: подтверждение
удаления живёт inline в строке списка, выбор клинрека — нативный `<select>` с полусотней длинных
названий, уведомлений о результате действий нет вообще. При этом визуальная основа проекта (токены,
CSS-модули, презентационные компоненты) хорошая — менять нужно оформление и примитивы, а не
архитектуру.

## What Changes

- **Визуальный язык «клинический редактор»**: тёплая бумажная палитра, петроль как единственный акцент,
  маркерная (жёлтая) подсветка цитаты, serif в заголовках и цитатах, mono для кодов МКБ и цифр.
- **Типографика**: self-host `Literata`, `Inter`, `JetBrains Mono` (все с кириллицей, OFL) вместо
  системного `Segoe UI`; единая типо-шкала и вертикальный ритм вместо захардкоженных 12–20px.
- **Стек фронтенда**: Tailwind CSS v4 (`@tailwindcss/vite`) + shadcn/ui поверх Radix; токены остаются
  единственным источником в `styles/tokens.css` и связываются с Tailwind через `@theme inline`.
  CSS-модули удаляются по мере перевода экранов, в одном компоненте оба подхода не смешиваются.
  Правило в `AGENTS.md` про «минимальный UI-kit» заменяется конкретным описанием стека.
- **Библиотека**: нумерованный список с линейками вместо стопки карточек, фильтр статусов чипами,
  статус точкой с текстом, действия по `:hover`/`:focus-within`, skeleton вместо блока загрузки,
  форма загрузки — в панели по кнопке в шапке (в пустой библиотеке — dropzone на весь экран).
- **Просмотрщик**: липкий тулбар с полем номера страницы, режим «по ширине», клавиатурные сокращения,
  кнопка «к цитате», цитата в боковой панели рядом с PDF, маркерная подсветка вместо синей заливки.
- **Форма протокола**: две колонки, ошибки рядом с полем и фокус на первое невалидное при отправке,
  выбор клинрека через combobox с поиском, закреплённая кнопка отправки.
- **Доступность**: `:focus-visible` на всех интерактивных элементах, контраст AA для текста и статусов,
  `prefers-reduced-motion`, диалоги с фокус-трапом, `Esc` и возвратом фокуса на инициатора.
- **BREAKING** (для внешнего вида, не для API): `GUIDELINE_*` подписи и тексты ошибок сохраняются,
  но разметка экранов меняется полностью; тесты, читающие разметку по классам, переписываются.

Вне области изменения: экран вердикта (у бэкенда пока нет эндпоинта вердикта), тёмная тема, мобильная
адаптация ниже 1024px, серверные счётчики статусов и поиск по названию (требуют нового API), любые
изменения бэкенда.

## Capabilities

### New Capabilities

- `design-system`: визуальная основа приложения — токены, типографика и шрифты, палитра, примитивы
  (кнопка, поле, карточка, бейдж, диалог, комбобокс, тост), состояния загрузки и пустых экранов,
  правила доступности и движения. Оунит то, что должно быть одинаковым на всех экранах, чтобы экраны
  не расходились снова.

### Modified Capabilities

- `guideline-library`: загрузка открывается панелью по кнопке, подтверждение удаления — в диалоге
  (клавиатура, `Esc`, возврат фокуса), состояния списка показываются skeleton-строками; требования
  о фильтре, статусе, прогрессе и кодах МКБ не меняются.
- `guideline-viewer`: переход к странице по введённому номеру, режим «по ширине», клавиатурная
  навигация и возврат к цитате; требования о подсветке и адресном переходе не меняются.
- `protocol-form`: ошибки полей показываются рядом с полем и фокус уходит на первое невалидное,
  выбор клинрека — combobox с поиском по названию и кодам МКБ.

## Impact

- **Код**: весь `frontend/src` — `styles/`, `components/`, `pages/`; `vite.config.ts` (плагин Tailwind);
  `index.html` (шрифты, preload); настройки `eslint` (плагин `jsx-a11y`). Бэкенд не затрагивается.
- **Зависимости**: `tailwindcss`, `@tailwindcss/vite`, `tailwind-merge`, `class-variance-authority`,
  `clsx`, `lucide-react`, пакеты `@radix-ui/react-*` под диалог, комбобокс, тост, тултип;
  dev — `eslint-plugin-jsx-a11y`. Шрифты лежат в репозитории (`frontend/public/fonts`) и не тянутся из
  CDN, чтобы сборка оставалась автономной.
- **Документация процесса**: правило в `AGENTS.md` заменяется описанием стека и правилом миграции.
- **Тесты**: `GuidelineRow.test.tsx`, `UploadForm.test.tsx`, `routes.test.tsx`, `ViewerPage`/`PdfViewer`
  проверки — обновляются вместе с разметкой; появляется `jsdom` + `@testing-library/react`, потому что
  диалог и combobox без DOM не проверить.
- **Сборка**: Vite собирает CSS через Tailwind; nginx отдаёт хэшированные шрифты и стили как статику —
  конфигурация nginx не меняется.
