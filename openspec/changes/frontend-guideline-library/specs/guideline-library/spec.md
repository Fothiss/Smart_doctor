# Spec Delta

## Purpose

Даёт врачу библиотеку загруженных клинических рекомендаций: загрузку PDF, обзор списка с состоянием
каждого документа и понятные отказы, когда файл не принят.

## ADDED Requirements

### Requirement: Список клинреков

Интерфейс SHALL показывать все загруженные клинреки, свежие загрузки первыми, с названием, именем
исходного файла, размером, датой загрузки и текущим статусом обработки.

#### Scenario: Открытие библиотеки с загруженными клинреками

- **WHEN** пользователь открывает экран библиотеки, и в хранилище есть клинреки
- **THEN** отображается список, отсортированный от свежих загрузок к старым
- **AND** каждый элемент показывает название, размер, дату загрузки и статус

#### Scenario: Библиотека без клинреков

- **WHEN** пользователь открывает экран библиотеки, и в хранилище нет ни одного клинрека
- **THEN** отображается сообщение о пустой библиотеке и предложение загрузить PDF
- **AND** пустой список не показывается как ошибка

### Requirement: Фильтр по статусу

Интерфейс SHALL позволять ограничить список одним статусом обработки и MUST показывать, какой фильтр
применён сейчас.

#### Scenario: Применение фильтра

- **WHEN** пользователь выбирает статус в фильтре
- **THEN** список содержит только клинреки с этим статусом
- **AND** выбранный фильтр виден в интерфейсе

#### Scenario: Сброс фильтра

- **WHEN** пользователь сбрасывает фильтр
- **THEN** список снова содержит клинреки всех статусов

### Requirement: Постраничная догрузка списка

Интерфейс SHALL загружать список страницами и MUST NOT показывать один и тот же клинрек дважды после
догрузки.

#### Scenario: Догрузка следующей страницы

- **WHEN** пользователь запрашивает следующую страницу, и сервер вернул её полностью
- **THEN** новые клинреки добавляются в конец существующего списка
- **AND** управление догрузкой остаётся доступным

#### Scenario: Список исчерпан

- **WHEN** сервер вернул страницу короче запрошенного размера
- **THEN** управление догрузкой больше не предлагается как доступное

### Requirement: Загрузка PDF клинрека

Интерфейс SHALL принимать PDF-файл и необязательное название клинрека, отправлять их на сервер и после
успеха MUST показывать созданный клинрек в списке.

#### Scenario: Успешная загрузка

- **WHEN** пользователь выбирает PDF-файл и подтверждает загрузку
- **THEN** клинрек создаётся на сервере со статусом `uploaded`
- **AND** созданный клинрек появляется в списке библиотеки

#### Scenario: Название не указано

- **WHEN** пользователь загружает PDF, не заполнив название
- **THEN** клинрек создаётся, и его названием становится имя файла без расширения

#### Scenario: Выбор файла

- **WHEN** пользователь выбирает файл в диалоге или перетаскивает его в область загрузки
- **THEN** выбранный файл и его размер видны до подтверждения загрузки
- **AND** загрузка не начинается без подтверждения

### Requirement: Ход загрузки

Интерфейс SHALL показывать ход передачи файла и MUST блокировать повторную отправку того же файла,
пока передача не завершилась.

#### Scenario: Передача идёт

- **WHEN** загрузка файла началась и ещё не завершилась
- **THEN** интерфейс показывает прогресс передачи
- **AND** повторный запуск загрузки недоступен

#### Scenario: Передача завершена

- **WHEN** сервер ответил на запрос загрузки
- **THEN** индикатор прогресса исчезает

### Requirement: Отказ при неподходящем файле

Интерфейс SHALL показывать причину отказа, когда сервер отклонил файл как пустой, не PDF или
превышающий допустимый размер, и MUST сохранять уже выбранный файл доступным для замены.

#### Scenario: Файл не является PDF

- **WHEN** сервер отвечает `400` на загрузку
- **THEN** интерфейс показывает текст причины отказа
- **AND** список библиотеки не меняется

#### Scenario: Файл превышает лимит размера

- **WHEN** сервер отвечает `413` на загрузку
- **THEN** интерфейс показывает, что файл превышает допустимый размер

### Requirement: Отказ при дубликате

Интерфейс SHALL при ответе `409` сообщать, что PDF с таким содержимым уже загружен, и MUST давать
переход к этому существующему клинреку.

#### Scenario: Повторная загрузка того же PDF

- **WHEN** сервер отвечает `409` и передаёт идентификатор уже загруженного клинрека
- **THEN** интерфейс сообщает о дубликате и показывает ссылку на существующий клинрек
- **AND** переход по ссылке открывает этот клинрек

### Requirement: Состояния экрана библиотеки

Интерфейс SHALL различать загрузку данных, пустой результат и ошибку получения списка.

#### Scenario: Список загружается

- **WHEN** запрос списка ещё не завершился
- **THEN** интерфейс показывает индикатор загрузки

#### Scenario: Ошибка получения списка

- **WHEN** запрос списка завершился ошибкой
- **THEN** интерфейс показывает сообщение об ошибке и способ повторить запрос
- **AND** пустой список при этом не показывается

### Requirement: Достоверность статуса обработки

Интерфейс SHALL показывать статус клинрека ровно таким, каким его вернул сервер, и MUST NOT помечать
клинрек как готовый к проверке или как обрабатываемый, пока сервер не сообщил такой статус.

#### Scenario: Клинрек только загружен

- **WHEN** статус клинрека — `uploaded`
- **THEN** интерфейс показывает его как загруженный, а не как готовый к проверке

#### Scenario: Обработка завершилась ошибкой

- **WHEN** статус клинрека — `failed` и сервер передал причину
- **THEN** интерфейс показывает признак ошибки и её причину

### Requirement: Текст ошибки API для пользователя

Интерфейс SHALL извлекать читаемое сообщение из ответа сервера независимо от того, передан `detail`
строкой или объектом, и MUST NOT показывать пользователю необработанное представление объекта.

#### Scenario: Ошибка со строковым detail

- **WHEN** сервер отвечает ошибкой, где `detail` — строка
- **THEN** интерфейс показывает эту строку

#### Scenario: Ошибка с объектным detail

- **WHEN** сервер отвечает ошибкой, где `detail` — объект
- **THEN** интерфейс показывает содержательное сообщение, а не сериализованный объект
