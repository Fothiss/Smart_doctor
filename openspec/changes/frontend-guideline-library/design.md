# Design

## Context

См. `proposal.md` — Why. Ограничения, которые формируют подход:

- **`frontend/` пуст по коду, но не по обвязке.** Есть `Dockerfile` (ждёт `package.json`/`package-lock.json`,
  `npm ci`, `npm run build`, затем nginx) и `nginx.conf`. Значит `docker compose up` **уже сейчас падает**
  на сборке сервиса `frontend` — `COPY package.json` не находит файл. Обвязка задаёт контракт: собранная
  статика в `/app/dist`, SPA-роутинг через `try_files`, API через `location /api/` → `backend:8000`.
- **Контракт API зафиксирован** в `openapi.json` (снимок) и `backend/API.md`. Реализованы пять операций;
  всё остальное помечено 🚧. Формат ошибки — `{"detail": ...}`: строка для 400/404/413/422, объект
  `{message, guideline_id}` для 409.
- **`Range` на PDF поддержан сервером** и покрыт тестом (`backend/tests/test_guidelines_api.py:148`
  проверяет `Content-Range`). Просмотрщик может рассчитывать на частичную загрузку, а не на файл целиком.
- **Ingestion-пайплайна нет.** `GuidelineStatus` объявлен как `uploaded|processing|ready|failed`, но
  сервис всегда пишет `uploaded`, `error` всегда `null`, `version` всегда `1`. Опрос статусов и любые
  обещания «готово к проверке» сейчас бессмысленны.
- **Ограничения проекта** из `AGENTS.md`: строгий TypeScript, презентационные компоненты, логика в
  хуках/сторе/API-клиенте, минимальный UI-kit без тяжёлых библиотек, рабочие `npm run dev/build/lint`,
  пути `src/pages`, `src/components`, `src/api`, `src/store`.
- **`GET /api/guidelines` не отдаёт `total`** и не ограничивает `limit` сверху: пагинация строится на
  `offset`/`limit` без знания общего количества.
- Рабочий каталог — `C:\Users\highs\OneDrive\Документы\GitHub\smart_doctor` (OneDrive + кириллица в пути).
- **Локальный запуск без контейнеров проверен:** канон — `python app/__main__.py` из `backend/`
  (та же команда в `Dockerfile`), `backend/.venv` собран (Python 3.12.8). `python` в `PATH` — заглушка
  Microsoft Store, `uv` в `PATH` нет (лежит в `backend/.venv\Scripts\uv.exe`), а `.ps1` без подписи
  заблокированы политикой `AllSigned` — подстановки для агента зафиксированы в `AGENTS.md`. Порты 8000
  и 5173 свободны. Docker Desktop не запущен, поэтому сценарии через `nginx` в этом изменении не проверяются.
- **В хранилище уже есть клинрек для проверки:** `5fc51635-7cdf-4efe-99dd-fa7028434376` — «Гипертензия»,
  `КР62_3.pdf`, 3 202 485 байт, настоящий `%PDF-`. Библиотека не пуста на первом запуске, а для проверки
  дубликата годится повторная загрузка того же файла.

## Goals / Non-Goals

**Goals:**

- Рабочий вертикальный срез «загрузил PDF → увидел в библиотеке → открыл оригинал», проверяемый в
  браузере и в собранном контейнере.
- Один слой доступа к API, из которого будущие экраны (протокол, отчёт, история) берут типы и обработку
  ошибок, а не переписывают их.
- Просмотрщик, готовый принять подсветку чанка без переделки: точка входа `goTo(page, bbox?)` уже есть,
  вызывать её пока нечем.

**Non-Goals:**

- Подсветка чанков, аннотации, текстовый слой и поиск по документу — до появления `GET /api/chunks/{id}`.
- Непрерывная прокрутка и предзагрузка соседних страниц — только постраничный режим.
- Кэш ответов, офлайн-режим, SSR.
- Изменения бэкенда: CORS, пагинация с `total`, статусы, версионирование клинреков.
- Экраны протокола, отчёта, чата и истории — даже как заглушки.

## Decisions

### 1. Сборка и стек

Vite + React + TypeScript в strict-режиме, `react-router-dom` для маршрутов, стили — CSS Modules плюс
токены в CSS-переменных.

- *Альтернатива — Next.js*: SSR и серверные роуты здесь не нужны, а `Dockerfile` уже описывает
  nginx-раздачу статики; смена фреймворка тянула бы за собой переделку обвязки.
- *Альтернатива — Tailwind или Mantine*: `AGENTS.md` требует минимальный UI-kit, а вес и кривая входа
  не окупаются на двух экранах. CSS Modules дают локальную область имён без рантайма.

### 2. Доступ к API без библиотеки кэша

`src/api/` — тонкие типизированные функции (`listGuidelines`, `uploadGuideline`, `getGuideline`,
`guidelineFileUrl`) и класс `ApiError`; загрузка — через `XMLHttpRequest` ради прогресса передачи.
Состояние экранов — локальные хуки в `src/hooks/`.

- *Альтернатива — TanStack Query*: главный её выигрыш здесь — опрос статусов и инвалидация кэша, но
  статус не меняется (нет ingestion), а страниц две. Библиотеку добавим вместе с `checks`/`reports`,
  когда появится что опрашивать; слой API к этому готов.
- *Альтернатива — `fetch` без прогресса*: `fetch` не умеет отдавать прогресс отправки, а файлы до 50 МБ
  без индикатора выглядят как зависший интерфейс.

### 3. Типы из контракта, а не руками

`openapi-typescript` как dev-зависимость, скрипт `npm run gen:api` читает `openapi.json` из корня и
пишет `src/api/schema.d.ts`. Руками — только обёртки и разбор `detail`.

- *Альтернатива — типы руками*: `Guideline` уже описан дважды (Pydantic и OpenAPI), третий рукописный
  экземпляр разъедется при первом же изменении схемы.
- *Альтернатива — генерация с живого `/openapi.json`*: точнее снимка, но требует поднятого бэкенда в
  каждой сборке. Пока источник — файл в корне, обновление снимка остаётся ручным шагом.

### 4. Маршруты и адресация

| Адрес | Экран |
|---|---|
| `/` | редирект на `/library` |
| `/library` | список, загрузка, фильтр; состояние фильтра — в query-параметрах |
| `/library/:guidelineId/view?page=N` | просмотрщик; страница в адресе |
| `*` | 404 |

Фильтр и номер страницы живут в адресе, поэтому возврат из просмотра восстанавливает список (требование
спеки) без ручного сохранения состояния в сторе, а кнопка «назад» браузера работает ожидаемо.

### 5. Просмотрщик PDF

`pdfjs-dist` напрямую, worker подключается через `import workerUrl from 'pdfjs-dist/build/pdf.worker.min.mjs?url'`
и `GlobalWorkerOptions.workerSrc`. Документ грузится по адресу `/api/guidelines/{id}/file`, `pdf.js`
сам использует `Range`.

Компонент `PdfViewer` презентационный: страница, масштаб, `onPageChange`. Хук `usePdfDocument` владеет
загрузкой и `PDFDocumentProxy`. Наружу — `viewerRef` с `goTo(page, bbox?)`.

- *Альтернатива — `react-pdf`*: обёртка скрывает `Range`-поведение и версию `pdfjs-dist`, а подсветка
  области потребует доступа к viewport и трансформациям, которые всё равно придётся брать из `pdf.js`.

Реализовано чуть больше, чем «интерфейс на будущее»: `goTo` не просто принимает `bbox`, а рисует
прямоугольник подсветки поверх canvas. Иначе параметр остался бы мёртвым, а так подключение
`GET /api/chunks/{chunk_id}` сводится к передаче координат. Углы переводятся по одному
(`lib/bbox.ts`): `convertToViewportRectangle` в PDF.js 6 удалён, остался `convertToViewportPoint`.

### 6. Область тестов

Vitest в окружении `node` покрывает `src/api` (разбор `detail`, query-параметры, адрес файла, подписи
статусов), `src/store` (слияние страниц, порядок и параметры запросов, состояния экрана, параметры
адреса, отказы загрузки) и `src/lib` (формат, масштаб, координаты), плюс `npm run build` как проверка
типов и сборки worker'а.

Сверх плана добавлены дымовые рендеры через `react-dom/server`: маршруты и строка списка собираются без
ошибок — это единственная проверка отрисовки, доступная без браузера. Маркеры `<!-- -->`, которые React
вставляет между текстовыми узлами, снимаются перед проверками содержимого.

- *Альтернатива — `jsdom` + `@testing-library/react`*: дала бы тесты хуков и кликов, но тянет DOM-окружение
  ради двух экранов, а canvas и drag&drop в ней всё равно не проверить.
- За браузером остаётся: отрисовка страниц PDF, drag&drop, прогресс передачи, поведение при недоступном
  бэкенде и фильтр в живом интерфейсе.

### 7. Стили и локализация

Токены (цвета статусов, отступы, радиусы) в `src/styles/tokens.css`; статусы кодируются цветом и текстом
одновременно. Даты — `Intl.DateTimeFormat('ru-RU')`, размеры — `Intl.NumberFormat` с единицами КБ/МБ.

## Risks / Trade-offs

- **`nginx` может сломать `Range`** (`proxy_buffering`, `gzip`) → превратит `206` в `200` и заставит
  PDF.js тянуть файл целиком. → `Range` проверяется напрямую на бэкенде в этом изменении; проверка через
  nginx вынесена в follow-up до доступного Docker, при необходимости — `proxy_buffering off` и `gzip off`
  для `/api/`.
- **Worker PDF.js может не попасть в прод-сборку** (в dev работает, в собранном бандле — белый экран). →
  Проверка просмотра на `npm run build && npm run preview` и в контейнере; worker импортируется через
  `?url`, а не из `public/`.
- **Статусы обещают больше, чем есть**: `ready`/`processing` недостижимы, `error` всегда пуст. → Спека
  запрещает выдавать `uploaded` за готовность; интерфейс показывает ровно серверное значение.
- **`total` нет, верхней границы `limit` нет** → нельзя показать «N из M» и нельзя ограничить выборку. →
  Догрузка останавливается по короткой странице; при появлении `total` меняется только хук списка.
- **`409` приходит объектом, остальные ошибки — строкой** → наивный `detail` в UI даёт `[object Object]`.
  → Отдельное требование спеки и отдельный тест на оба варианта.
- **`node_modules` внутри OneDrive** (путь с кириллицей, синхронизация, блокировки файлов) замедляет
  установку и иногда даёт `EPERM`. → `node_modules`, `dist` и `.vite` добавлены в `.gitignore`; при
  проблемах — исключение каталога из синхронизации OneDrive.
- **Главный чанк собранного бандла — 709 КБ (218 КБ gzip)**, потому что `pdfjs-dist` попадает в общий
  бандл, хотя экрану библиотеки он не нужен. → Для локального single-user MVP не критично; при
  необходимости библиотека выносится динамическим импортом в `usePdfDocument`.
- **`npm.ps1` без цифровой подписи** в этом окружении (политика Execution Policy). → Вызывать `npm.cmd`
  либо `node node_modules/npm/bin/npm-cli.js`, не `npm`.
- **`docker compose up` сейчас нерабочий** из-за отсутствия `package.json` → до завершения изменения
  сервис `frontend` не собрать; `backend` и `db` поднимаются как раньше.

## Migration Plan

1. До изменения `docker compose up` падает на сборке `frontend` — это исходное состояние, не регрессия.
2. Изменение добавляет `package.json` и `src/`, после чего `npm ci` и `npm run build` в `Dockerfile`
   начинают собирать рабочий образ; правки `nginx.conf` (при необходимости) применяются вместе с ним.
3. Первый запуск после изменения: `cd frontend && npm ci && npm run dev` для разработки; для проверки
   прод-пути без контейнеров — `npm run build && npm run preview`; полный путь через nginx —
   `docker compose up -d --build frontend`, когда Docker Desktop запущен.
4. Откат — возврат коммита `frontend/`: сервис снова не собирается, но `backend`, `db` и хранилище PDF
   не затронуты; данные клинреков в `pdf_storage` и на диске сохраняются.

## Open Questions

- Постраничный режим против непрерывной прокрутки: если чтение длинных клинреков окажется неудобным,
  режим просмотра меняется — на требования и разбиение задач это не влияет.
- Нужен ли CORS на бэкенде: при раздаче фронта через `nginx` (как сейчас) — нет; понадобится, только
  если фронт начнут хостить отдельно, и тогда это отдельное изменение бэкенда.
- Судьба `openapi.json` в корне: остаётся ручным снимком или обновляется из живого `/openapi.json` в CI —
  решится, когда появится CI; на `src/api/` это не влияет.
