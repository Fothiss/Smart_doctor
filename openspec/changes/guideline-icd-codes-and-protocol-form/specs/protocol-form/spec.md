# Spec Delta

## Purpose

Даёт врачу ввести врачебный протокол структурированной формой и получить его серверную проверку на
корректность вместе с набором атомарных пунктов, которые пойдут в проверку на соответствие клинреку.

## ADDED Requirements

### Requirement: Поля формы протокола

Интерфейс SHALL предоставлять форму протокола с полями: жалобы, код МКБ-10 диагноза, название
диагноза, описание диагноза и назначения. Жалобы, код МКБ и название диагноза SHALL быть
обязательными, описание диагноза — необязательным.

#### Scenario: Форма заполнена

- **WHEN** пользователь заполнил жалобы, код МКБ, название диагноза и нажал отправку
- **THEN** форма проходит клиентскую проверку и отправляется на сервер
- **AND** описание диагноза можно оставить пустым

#### Scenario: Обязательное поле пустое

- **WHEN** жалобы, код МКБ или название диагноза пусты
- **THEN** отправка недоступна, а незаполненное поле помечено как обязательное
- **AND** запрос на сервер не отправляется

### Requirement: Проверка формата кода МКБ

Интерфейс и сервер SHALL принимать код МКБ-10 вида «латинская заглавная буква, две цифры,
необязательная точка и одна-две цифры» (например `I10`, `I10.1`) и MUST отклонять любой другой
код с указанием ожидаемого формата.

#### Scenario: Корректный код

- **WHEN** пользователь вводит `i10.1`
- **THEN** код принимается и нормализуется к верхнему регистру — `I10.1`

#### Scenario: Некорректный код

- **WHEN** пользователь вводит `10`, `I1` или `гипертензия` в поле кода МКБ
- **THEN** код отклоняется, и интерфейс показывает ожидаемый формат
- **AND** форма не отправляется на сервер

### Requirement: Назначения как отдельные пункты

Интерфейс SHALL позволять добавить любое число назначений и MUST хранить каждое назначение
отдельным пунктом с видом — препарат или процедура — и названием. Дозировка, кратность и
длительность приёма SHALL быть необязательными и MUST быть доступны только для препаратов.

#### Scenario: Добавление назначения

- **WHEN** пользователь добавляет назначение и указывает его вид и название
- **THEN** назначение появляется в форме отдельным пунктом

#### Scenario: Удаление назначения

- **WHEN** пользователь удаляет назначение
- **THEN** пункт исчезает из формы, а остальные назначения не меняются

#### Scenario: Поля дозировки у процедуры

- **WHEN** вид назначения — процедура
- **THEN** поля дозировки, кратности и длительности не предлагаются

### Requirement: Выбор клинрека для протокола

Интерфейс SHALL позволять выбрать клинрек, по которому будет проверяться протокол, и MUST предлагать
только клинреки в статусе `ready`. Если введён код МКБ диагноза, интерфейс SHALL показывать первыми
клинреки, у которых среди кодов МКБ есть совпадающий.

#### Scenario: Список доступных клинреков

- **WHEN** пользователь открывает выбор клинрека в форме
- **THEN** в списке есть только клинреки в статусе `ready`
- **AND** клинреки, ещё не прошедшие индексацию, в списке отсутствуют

#### Scenario: Подсказка по коду диагноза

- **WHEN** введён код МКБ `I10`, и среди клинреков есть документ с кодом `I10`
- **THEN** этот клинрек показывается в списке первым

#### Scenario: Клинреков нет

- **WHEN** ни один клинрек не готов к проверке
- **THEN** интерфейс сообщает, что выбирать нечего, и предлагает перейти в библиотеку

### Requirement: Серверная валидация черновика протокола

Сервер SHALL принимать черновик протокола — идентификатор и версию клинрека вместе с формой — и
отвечать подтверждённым черновиком с разрешёнными полями выбранного клинрека. Валидация MUST NOT
сохранять форму и MUST NOT выдавать идентификатор протокола.

#### Scenario: Черновик корректен

- **WHEN** форма заполнена верно, а клинрек существует и готов к проверке
- **THEN** сервер отвечает подтверждённым черновиком и сведениями о выбранном клинреке

#### Scenario: Форма не проходит проверку

- **WHEN** обязательное поле пустое или код МКБ не соответствует формату
- **THEN** сервер отвечает `400` и указывает, какое поле отклонено
- **AND** черновик не сохраняется

#### Scenario: Клинрек не найден

- **WHEN** передан идентификатор клинрека, которого нет в библиотеке
- **THEN** сервер отвечает `404`

#### Scenario: Клинрек не готов к проверке

- **WHEN** выбранный клинрек ещё не в статусе `ready`
- **THEN** сервер отвечает `409` и указывает текущий статус клинрека

### Requirement: Атомарные пункты протокола

Ответ валидации SHALL содержать атомарные пункты протокола — по одному утверждению на пункт — в
детерминированном порядке: жалобы, диагноз, описание диагноза, затем каждое назначение отдельно.
Пустое необязательное поле MUST NOT давать пункт.

#### Scenario: Одно назначение — одно утверждение

- **WHEN** в протоколе два препарата и одна процедура
- **THEN** ответ содержит по одному пункту на каждое назначение
- **AND** пункты не склеиваются между собой

#### Scenario: Пустое описание диагноза

- **WHEN** описание диагноза не заполнено
- **THEN** в списке пунктов нет пункта описания диагноза
- **AND** остальные пункты сохраняют порядок

### Requirement: Черновик не сохраняется

Интерфейс MUST NOT обещать сохранение черновика: после перезагрузки страницы форма пуста. Повторная
отправка MUST быть возможна.

#### Scenario: Перезагрузка страницы

- **WHEN** пользователь перезагружает страницу формы после успешной валидации
- **THEN** форма пуста, а введённые ранее значения недоступны

#### Scenario: Повторная отправка

- **WHEN** валидация завершилась отказом
- **THEN** введённые значения остаются в форме, и отправку можно повторить
