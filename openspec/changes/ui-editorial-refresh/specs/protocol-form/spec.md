# Spec Delta

## MODIFIED Requirements

### Requirement: Поля формы протокола

Интерфейс SHALL предоставлять форму протокола с полями: жалобы, код МКБ-10 диагноза, название
диагноза, описание диагноза и назначения. Жалобы, код МКБ и название диагноза SHALL быть
обязательными, описание диагноза — необязательным.

#### Scenario: Форма заполнена

- **WHEN** пользователь заполнил жалобы, код МКБ, название диагноза и нажал отправку
- **THEN** форма проходит клиентскую проверку и отправляется на сервер
- **AND** описание диагноза можно оставить пустым

#### Scenario: Обязательное поле пустое

- **WHEN** жалобы, код МКБ или название диагноза пусты, и пользователь нажал отправку
- **THEN** запрос на сервер не отправляется
- **AND** незаполненные поля помечены как обязательные
- **AND** фокус переходит на первое из них

### Requirement: Выбор клинрека для протокола

Интерфейс SHALL позволять выбрать клинрек, по которому будет проверяться протокол, и MUST предлагать
только клинреки в статусе `ready`. Если введён код МКБ диагноза, интерфейс SHALL показывать первыми
клинреки, у которых среди кодов МКБ есть совпадающий. Выбор SHALL поддерживать поиск по названию и
кодам МКБ.

#### Scenario: Список доступных клинреков

- **WHEN** пользователь открывает выбор клинрека в форме
- **THEN** в списке есть только клинреки в статусе `ready`
- **AND** клинреки, ещё не прошедшие индексацию, в списке отсутствуют

#### Scenario: Подсказка по коду диагноза

- **WHEN** введён код МКБ `I10`, и среди клинреков есть документ с кодом `I10`
- **THEN** этот клинрек показывается в списке первым

#### Scenario: Поиск по списку клинреков

- **WHEN** пользователь ввёл часть названия клинрека или код МКБ в поиск
- **THEN** в списке остаются только подходящие клинреки
- **AND** выбор можно сделать стрелками и подтвердить клавишей Enter

#### Scenario: Поиск без совпадений

- **WHEN** поиск не нашёл ни одного готового клинрека
- **THEN** интерфейс сообщает, что подходящих клинреков нет
- **AND** уже выбранный ранее клинрек не теряется

#### Scenario: Клинреков нет

- **WHEN** ни один клинрек не готов к проверке
- **THEN** интерфейс сообщает, что выбирать нечего, и предлагает перейти в библиотеку

## ADDED Requirements

### Requirement: Указание на невалидное поле

Интерфейс SHALL показывать ошибку рядом с тем полем, к которому она относится, и MUST NOT полагаться
только на общий список ошибок в конце формы. При попытке отправки невалидной формы фокус SHALL
переходить на первое невалидное поле.

#### Scenario: Ошибка рядом с полем

- **WHEN** в форме есть невалидные поля
- **THEN** у каждого из них видно сообщение с причиной
- **AND** поле помечено как невалидное

#### Scenario: Фокус на первое невалидное поле

- **WHEN** пользователь нажал отправку, и форма невалидна
- **THEN** запрос на сервер не отправляется
- **AND** фокус оказывается на первом невалидном поле
- **AND** это поле видно без ручной прокрутки

#### Scenario: Исправление снимает ошибку

- **WHEN** пользователь исправил поле с ошибкой
- **THEN** ошибка этого поля исчезает
- **AND** ошибки остальных полей остаются на месте

### Requirement: Просьба выбрать клинрек

Если форма заполнена верно, но клинрек не выбран, интерфейс SHALL не отправлять запрос и MUST
объяснять, чего не хватает, оставляя введённые значения на месте.

#### Scenario: Клинрек не выбран

- **WHEN** пользователь нажал отправку с заполненной формой, но без выбранного клинрека
- **THEN** запрос на сервер не отправляется
- **AND** интерфейс сообщает, что нужно выбрать клинрек
- **AND** введённые значения остаются в форме
