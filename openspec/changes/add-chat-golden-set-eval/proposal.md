# Proposal

## Why

Чат по клинрекам — единственная AI-функция проекта, у которой нет измеримого качества: переписывание
запроса и векторный поиск правятся «на глаз», и отличить улучшение от регрессии нечем. Нужен
эталонный набор, прогон и отчёт, которые дают одно число до и после правки одного компонента.

## What Changes

- Новый каталог `backend/eval/` вне пакета `app` и вне `tests`: набор кейсов, раннер, отчёты.
- Эталонный набор из 20 кейсов по готовому клинреку «Гипертензия» (КР 62/3, 427 чанков).
- Одноразовый дампер чанков из локального Qdrant: без него нельзя выбрать ожидаемые `chunk_id`.
- Раннер `run.py`: `rewrite` → `search` → две проверки на кейс → JSON-отчёт и таблица в stdout,
  с замером времени на каждый этап.
- Слот для правки промпта: система-промпт переписывания берётся из `variants/rewrite_<x>.md`, а не
  из константы `REWRITE_SYSTEM`. Прод-код не меняется.
- Два отчёта, коммитимых в репозиторий: `reports/a.json` (baseline) и `reports/b.json` (после правки).
- `EVAL.md` с описанием набора, критериев и сравнением `A → B`.

## Capabilities

### New Capabilities

- `chat-eval`: измеримое качество чата — эталонный набор, критерии прохождения, запуск прогона,
  отчёт с разбивкой по этапам и сравнение версий.

### Modified Capabilities

Нет. Поведение чата не меняется: набор и раннер живут отдельно, промпт в проде остаётся прежним.

## Impact

- Новый код только в `backend/eval/` и `EVAL.md`.
- Переиспользуется прод-код: `QueryRewriter`-совместимый вызов `llm.structured(..., SearchQuery,
  role=REWRITE)`, приёмка тезиса `accept()` из `app/services/query_rewrite.py`, `RetrievalService`,
  `SentenceTransformerEmbedder`, `ChunkVectorStore.build`, `build_llm_client`.
- Внешние зависимости: реальные GigaChat (токен в `.env`) и локальный Qdrant — прогон не для CI.
- Стоимость прогона: 20 вызовов LLM на версию, без вызовов ответа.
