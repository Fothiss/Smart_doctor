# Тестовые наборы протокола

Ручные проверки эндпоинта `POST /api/protocols/validate` и формы `/protocol/new`.
Для каждого случая: что заполняем словами, что ожидаем и готовое тело запроса.

Проверка запросом:

```powershell
# 1. взять идентификатор готового клинрека
curl.exe -s "http://127.0.0.1:8000/api/guidelines?status=ready"

# 2. подставить его вместо <guideline_id> в JSON ниже
curl.exe -s -X POST "http://127.0.0.1:8000/api/protocols/validate" ^
  -H "Content-Type: application/json; charset=utf-8" ^
  --data-binary "@case.json"
```

Через интерфейс: `http://localhost:5173/protocol/new`.

Валидация **ничего не сохраняет**: идентификатора протокола в ответе нет, после перезагрузки страницы форма пуста. Это ожидаемо.

## 1. Полный протокол по гипертензии

**Поля**

- Жалобы: головная боль, головокружение.
- Код МКБ: `I10`, название диагноза: гипертензия.
- Описание диагноза: АГ 2 ст., риск 3.
- Назначения: препарат амлодипин 5 мг 1 раз в сутки без ограничения длительности; процедура ЭКГ без дозировки.

**Ожидание:** `200`. Пунктов в `statements` — пять, порядок: жалобы → диагноз → описание → назначение → процедура. В ответе `form.diagnosis.code` — `I10`.

**JSON**

```json
{
  "guideline_id": "<guideline_id>",
  "form": {
    "complaints": "Головная боль, головокружение",
    "diagnosis": { "code": "I10", "name": "Гипертензия" },
    "diagnosis_description": "АГ 2 ст., риск 3",
    "prescriptions": [
      { "kind": "drug", "name": "Амлодипин", "dose": "5 мг", "frequency": "1 раз в сутки" },
      { "kind": "procedure", "name": "ЭКГ" }
    ]
  }
}
```

**Ожидаемые `statements`**

```
Жалобы: Головная боль, головокружение
Диагноз: I10 — Гипертензия
Описание диагноза: АГ 2 ст., риск 3
Назначение: Амлодипин, 5 мг, 1 раз в сутки
Процедура: ЭКГ
```

## 2. ОРВИ, два препарата

**Поля**

- Жалобы: повышение температуры, насморк, боль в горле.
- Код МКБ: `J06.9`, название: острая инфекция верхних дыхательных путей.
- Описание диагноза: среднетяжёлое течение.
- Назначения: парацетамол 500 мг до 4 раз в сутки 3 дня; осельтамивир 75 мг 2 раза в сутки 5 дней.

**Ожидание:** `200`. Каждое назначение — отдельный пункт: два препарата дают два пункта `Назначение: ...` с дозировкой, кратностью и длительностью через запятую.

**JSON**

```json
{
  "guideline_id": "<guideline_id>",
  "form": {
    "complaints": "Повышение температуры, насморк, боль в горле",
    "diagnosis": { "code": "J06.9", "name": "Острая инфекция верхних дыхательных путей" },
    "diagnosis_description": "Среднетяжёлое течение",
    "prescriptions": [
      {
        "kind": "drug",
        "name": "Парацетамол",
        "dose": "500 мг",
        "frequency": "до 4 раз в сутки",
        "duration": "3 дня"
      },
      {
        "kind": "drug",
        "name": "Осельтамивир",
        "dose": "75 мг",
        "frequency": "2 раза в сутки",
        "duration": "5 дней"
      }
    ]
  }
}
```

**Ожидаемые `statements`**

```
Жалобы: Повышение температуры, насморк, боль в горле
Диагноз: J06.9 — Острая инфекция верхних дыхательных путей
Описание диагноза: Среднетяжёлое течение
Назначение: Парацетамол, 500 мг, до 4 раз в сутки, 3 дня
Назначение: Осельтамивир, 75 мг, 2 раза в сутки, 5 дней
```

**Ожидание:** `200`. Код сохраняется как `I10.1`; такой клинрек должен находиться фильтром библиотеки по коду `I10`.

    "diagnosis": { "code": "I10.1", "name": "Гипертензия с преимущественным поражением сердца" },

  }
}

## 8. Код МКБ неверного формата

**Поля**

- Жалобы: головная боль.
- Код МКБ: `гипертензия` вместо кода.
- Название диагноза: гипертензия.

**Ожидание:** `400`, `detail` начинается с `diagnosis.code:` и подсказывает пример `I10`.

**JSON**

```json
{

  "form": {

    "diagnosis": { "code": "гипертензия", "name": "Гипертензия" },

  }

```

**Другие неверные коды для проверки:** `10`, `I1`, `I100`, `I10.`.

## Что проверить заодно в интерфейсе

1. `/protocol/new`: до заполнения обязательных полей кнопка «Проверить форму» недоступна, под полями виден список проблем.
2. Поле «Код МКБ-10»: при вводе `I10` клинрек с кодом `I10` поднимается первым в списке выбора.
3. «Добавить препарат» / «Добавить процедуру»: пункты добавляются отдельно, «Удалить назначение» убирает только свой.
4. У процедуры нет полей дозировки, кратности и длительности.
5. После успешной валидации виден блок «Черновик принят» со сведениями о клинреке и списком пунктов; после отказа — причина, а введённые значения остаются на месте.
6. Перезагрузка страницы очищает форму — черновик не сохраняется.
